# 架构设计文档 vs 代码现状对比

> 对比文档: `docs/01-整体架构设计.md` | 日期: 2026-07-30

## 一、服务层组件差异

### 完全匹配（6个）

| 组件 | 文档路径 | 实际路径 | 状态 |
|------|----------|----------|------|
| ProxyServer | Services/Router/ | Services/Router/ | ✅ 一致 |
| ChannelRouterService | Services/Router/ | Services/Router/ | ✅ 一致 |
| ProtocolConverter | Services/Protocol/ | Services/Protocol/ | ✅ 一致 |
| DriverManager | Services/Protocol/ | Services/Protocol/ | ✅ 一致 |
| ProviderManager | Services/Provider/ | Services/Provider/ | ✅ 一致 |
| ChannelCodingStatusService | Services/CodingStatus/ | Services/CodingStatus/ | ✅ 一致 |

### 实现方式不同（5个）

| 文档组件 | 文档描述 | 实际情况 | 差异说明 |
|----------|----------|----------|----------|
| **LoadBalancer** | 独立类，支持加权轮询/最少连接/响应时间优先 | ❌ 不存在独立类 | 逻辑内嵌于 `ChannelRouterService`，方法: `applyLoadBalancing()`, `weightedRoundRobinBalance()` 等 |
| **FailoverStrategy** | 独立故障转移策略类 | ❌ 不存在独立类 | 逻辑内嵌于 `ChannelRouterService::getFallbackChannel()` 和 `ChannelSelector::select()` |
| **RetryStrategy** | 独立重试策略类 | ⚠️ 实际为 `RetryHandler` | 路径: `Services/Router/RetryHandler.php`，类名不同 |
| **CircuitBreaker** | 独立熔断器，支持熔断/半开/关闭三态 | ❌ 完全不存在 | 仅有 `ChannelHealthStatus` 枚举和渠道过滤，无熔断器模式 |
| **AuditService** | Services/Audit/AuditService | ⚠️ 实际为 `AuditLogger` | 路径: `Services/Router/Logger/AuditLogger.php`，属于 Logger 子包 |

### 文档未提及但实际存在

| 组件 | 路径 | 说明 |
|------|------|------|
| **ChannelSelector** | Services/Router/ChannelSelector.php | 渠道选择服务，支持故障转移和亲和性路由 |
| **StreamHandler** | Services/Router/Handler/ | 流式响应处理器 |
| **NonStreamHandler** | Services/Router/Handler/ | 非流式响应处理器 |
| **RequestLogger** | Services/Router/Logger/ | 请求日志记录器 |
| **ResponseLogger** | Services/Router/Logger/ | 响应日志记录器 |

## 二、中间件差异

| 文档中间件 | 实际情况 | 差异 |
|------------|----------|------|
| **AuditLogger** (中间件) | ❌ 不是中间件，是 Service 层 Logger | 文档将其列为中间件管道一环，实际在 ProxyServer 内部调用 |
| **CORS** | ⚠️ 使用 Laravel 内置 HandleCors | 无自定义实现 |
| **Authenticate** | ⚠️ 实际类名 `AuthenticateApiKey` | 命名不一致 |
| **RateLimiter** | ❌ 不存在自定义实现 | 仅有 Laravel 内置 RateLimiter |
| **CheckCodingQuota** | ✅ 存在且匹配 | — |

**文档未提及的中间件**:
- `SetAdminLocale` — 后台语言设置
- `SetUserInfo` — 用户信息设置

**文档中间件管道流程图需修正**: 实际管道为 `HandleCors → AuthenticateApiKey → CheckCodingQuota`，无 RateLimiter 和 AuditLogger 中间件。

## 五、架构图差异总结

### 文档描述 vs 实际架构

| 维度 | 文档描述 | 实际架构 |
|------|----------|----------|
| **策略模式** | LoadBalancer/FailoverStrategy/RetryStrategy 为独立策略类 | 内嵌于 ChannelRouterService，仅 RetryHandler 独立 |
| **熔断器** | 完整的 CircuitBreaker 三态模式 | ❌ 不存在 |
| **中间件管道** | 5层中间件（CORS→Auth→RateLimit→CodingQuota→Audit） | 3层（CORS→AuthenticateApiKey→CheckCodingQuota） |
| **日志记录** | AuditLogger 作为中间件 | AuditLogger 作为 Service，由 ProxyServer 调用 |
| **DTO 命名** | Standard/Provider/Token 前缀风格 | 简洁命名（Request/Response/StreamChunk/Usage） |
| **模型映射** | 独立 ModelMapping 模型 | 通过 ModelList + 关联关系实现 |
| **渠道选择** | ChannelRouterService 单一职责 | 拆分为 ChannelRouterService + ChannelSelector |

### 建议更新优先级

1. **高** — 中间件管道流程图（与实际不符，影响理解）
2. **高** — 服务组件表（LoadBalancer/FailoverStrategy/CircuitBreaker 不存在）
3. **中** — DTO 命名表（命名风格差异大）
4. **中** — 模型表（缺少 26 个实际模型，ModelMapping 不存在）
5. **低** — 目录结构图（基本框架正确，细节需补充）
