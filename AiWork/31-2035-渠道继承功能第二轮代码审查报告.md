#### S2 修复详情 ❌ 未修复

**文件**: `ChannelInheritanceResolver.php:174-184`

```php
// 当前代码（未修改）：
foreach (self::ARRAY_FIELDS as $field) {
    if ($mode->isOverride()) {
        $result[$field] = $currentConfig[$field] ?? [];
    } else {
        $parentValue = $result[$field] ?? [];
        $childValue = $currentConfig[$field] ?? [];
        $result[$field] = array_replace_recursive($parentValue, $childValue);  // ← 问题仍在
    }
}
```

**问题本质**: `forward_headers` 是索引数组（如 `['X-Header-A', 'X-Header-B']`），`array_replace_recursive` 对索引数组按键号覆盖：

```
父: ['X-Parent-Header']   (index 0)
子: ['X-Child-Header']    (index 0)
结果: ['X-Child-Header']  ← 父值被覆盖，不是合并！
```

**修复方案**: 对 `forward_headers` 使用 `array_unique(array_merge(...))`：

```php
if ($field === 'forward_headers') {
    $result[$field] = array_values(array_unique(array_merge(
        $parentValue ?? [],
        $childValue ?? []
    )));
} else {
    $result[$field] = array_replace_recursive($parentValue, $childValue);
}
```

同样的问题也存在于 `resolveArray()` 方法（第 278 行），需要一并修改。

## 二、修复引入的新问题

### NEW-1: 详情页 XSS 漏洞（严重）

**文件**: `ChannelController.php:304`

生效配置预览表格中，`$originalDisplay` 和 `$effectiveDisplay` **未经 HTML 转义**直接输出：

```php
// 第 283-284 行：值未转义
$originalDisplay = $originalValue ?: '<span class="text-muted">-</span>';
$effectiveDisplay = $effectiveValue ?: '<span class="text-muted">-</span>';

// 第 304 行：直接拼入 HTML
$html .= '<tr><td>'.e($label).'</td><td>'.$originalDisplay.'</td><td ...>'.$effectiveDisplay.'</td>...';
```

如果 `base_url`、`provider` 或 `api_key` 包含用户可控的 HTML/JS 代码（如 `<script>alert(1)</script>`），将在详情页执行。

**修复方案**: 对值进行转义，同时正确处理占位符 HTML：

```php
$originalDisplay = $originalValue ? e($originalValue) : '<span class="text-muted">-</span>';
$effectiveDisplay = $effectiveValue ? e($effectiveValue) : '<span class="text-muted">-</span>';
```

### NEW-2: parent_id 字段显示 XSS（中等）

**文件**: `ChannelController.php:219`

```php
return "<a href='{$url}'>{$parent->name} (ID: {$parent->id})</a>";
```

`$parent->name` 未经 `e()` 转义。如果渠道名称包含 HTML，会被注入到详情页。

然后通过 `use` 传递到闭包中。
