# 渠道父子关系逻辑梳理

## 一、架构设计概览

### 1.1 数据模型

```
channels 表核心字段：
├── id              # 主键
├── parent_id       # 父渠道 ID（NULL = 根渠道）
├── inherit_mode    # 继承模式：merge/override/extend
├── base_url        # API 基础 URL（可继承）
├── api_key         # API 密钥（可继承）
├── models          # 模型列表（已迁移至 channel_models 表）
├── config          # 扩展配置（可继承）
└── ...
```

### 1.2 继承关系示例

```
根渠道（OpenAI 基础配置）
│
├── 子渠道 A（GPT-4 专用）
│   ├── models: [gpt-4]
│   ├── weight: 5
│   └── 继承: base_url, api_key, config
│
├── 子渠道 B（GPT-3.5 专用）
│   ├── models: [gpt-3.5-turbo]
│   ├── weight: 3
│   └── 继承: base_url, api_key, config
│
└── 子渠道 C（覆盖继承）
    ├── models: [gpt-4o]
    ├── weight: 1
    └── override: 使用自己的 models
```

## 二、继承模式详解

### 2.1 Merge（合并继承）- 默认模式

**规则**：
- 数组类型：合并父子数组（去重）
- 对象类型：深度合并，子覆盖父
- 标量类型：子覆盖父

**示例**：
```php
// 父渠道
models: ["gpt-4", "gpt-3.5-turbo"]
config: {timeout: 120, retry: 3}

// 子渠道（merge）
models: ["gpt-4-turbo"]
config: {cache: true}

// 合并结果
models: ["gpt-4", "gpt-3.5-turbo", "gpt-4-turbo"]  // 合并去重
config: {timeout: 120, retry: 3, cache: true}      // 深度合并
```

### 2.2 Override（覆盖继承）

**规则**：
- 完全使用子渠道的值
- 忽略父渠道的对应字段

**示例**：
```php
// 父渠道
models: ["gpt-4", "gpt-3.5-turbo"]

// 子渠道（override）
models: ["gpt-4o"]

// 覆盖结果
models: ["gpt-4o"]  // 完全覆盖
```

### 2.3 Extend（扩展继承）

**规则**：
- 数组类型：子数组追加到父数组
- 对象类型：子对象合并到父对象
- 标量类型：子覆盖父

**示例**：
```php
// 父渠道
models: ["gpt-4"]
config: {timeout: 120}

// 子渠道（extend）
models: ["gpt-3.5-turbo"]
config: {retry: 3}

// 扩展结果
models: ["gpt-4", "gpt-3.5-turbo"]  // 追加
config: {timeout: 120, retry: 3}     // 合并
```

## 三、继承解析流程

### 3.1 加载渠道链（递归查询）

```sql
-- 递归查询父渠道链（最多 5 级）
WITH RECURSIVE channel_tree AS (
  -- 起点：目标渠道
  SELECT id, parent_id, 1 AS level
  FROM channels
  WHERE id = 5

  UNION ALL

  -- 递归：向上查找父渠道
  SELECT c.id, c.parent_id, ct.level + 1
  FROM channels c
  JOIN channel_tree ct ON c.id = ct.parent_id
  WHERE ct.level < 5  -- 限制最大层级
)
SELECT id FROM channel_tree ORDER BY level DESC;
```

**结果**：`[根渠道(1) → 中间渠道(3) → 目标渠道(5)]`

### 3.2 按层级合并配置

```php
// 伪代码流程
$config = [];

// 1. 从根渠道开始，逐层合并
foreach ($channelChain as $channel) {
    switch ($channel->inherit_mode) {
        case 'merge':
            $config = deep_merge($config, $channel->attributes);
            break;
        case 'override':
            $config = $channel->attributes;
            break;
        case 'extend':
            $config = array_extend($config, $channel->attributes);
            break;
    }
}

// 2. 缓存解析结果
Cache::put("cdapi:channel:resolved:{$id}", $config, 300);
```

## 五、约束与安全机制

### 5.1 层级限制

```
最大继承层级：5 级
目的：防止继承链过长导致性能问题
```

### 5.2 循环继承检测

```php
// 创建/更新渠道时检测循环
function detectCycle($channelId, $parentId): bool
{
    $visited = [$channelId];
    $current = $parentId;

    while ($current !== null) {
        if (in_array($current, $visited)) {
            return true;  // 检测到循环
        }
        $visited[] = $current;
        $current = Channel::find($current)->parent_id;
    }

    return false;
}
```

### 5.3 缓存一致性

```
更新渠道时需要：
1. 删除当前渠道的解析缓存
2. 删除所有子渠道的解析缓存
3. 触发继承链缓存失效
```

## 七、建议实现方案

### 7.1 创建继承解析服务

```php
// app/Services/Channel/ChannelInheritanceService.php
namespace App\Services\Channel;

class ChannelInheritanceService
{
    /**
     * 解析渠道完整配置（含继承）
     */
    public function resolveInheritedConfig(int $channelId): array;

    /**
     * 获取渠道继承链
     */
    public function getInheritanceChain(int $channelId): Collection;

    /**
     * 检测循环继承
     */
    public function detectCycle(int $channelId, ?int $parentId): bool;
}
```

### 7.2 集成到渠道路由流程

```php
// 在 ChannelRouterService::selectChannel() 中
$channel = Channel::find($channelId);

// 使用解析后的配置
$resolvedConfig = app(ChannelInheritanceService::class)
    ->resolveInheritedConfig($channel->id);

// 使用继承后的 base_url 和 api_key
$baseUrl = $resolvedConfig['base_url'];
$apiKey = $resolvedConfig['api_key'];
```

### 7.3 添加缓存层

```php
// 使用 Cache::remember 简化实现
$resolvedConfig = Cache::remember(
    "cdapi:channel:resolved:{$channelId}",
    300,
    fn() => $this->resolveInheritedConfig($channelId)
);
```

## 九、性能考量

### 9.1 查询优化

- 使用递归 CTE 查询一次性加载整条继承链
- 避免 N+1 查询问题
- 限制最大层级为 5 级

### 9.2 缓存策略

- 解析结果缓存 300 秒
- 渠道更新时主动失效缓存
- 批量更新时批量删除缓存

### 9.3 监控指标

- 继承解析耗时
- 缓存命中率
- 继承链平均深度
