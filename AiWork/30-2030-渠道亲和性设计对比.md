# 渠道亲和性设计 vs 现状对比

> 对比 `docs/12-渠道亲和性设计.md` 与当前代码实现的差异
> 日期: 2026-07-30

## 一、整体状态

功能已**基本完整实现**，核心链路（选路 → 缓存 → 记录 → 审计）贯通。存在若干"已定义未集成"的悬挂代码和实现与配置不匹配的问题。

## 二、关键差异（需修复）

### 2.1 `json` 组合策略未实现 ⚠️ 高优先级

| 层面 | 现状 |
|------|------|
| Admin 表单 | 提供 `json` 选项（"JSON序列化"） |
| Seeder | RooCode、Anthropic Messages 规则使用 `json` 策略 |
| KeyExtractor | `combineKeys()` / `generateKeyHash()` 的 `match` 语句**无 `json` 分支**，落入 `default` 退化为 `first` |

**影响**: 使用 `json` 策略的规则实际行为与 `first` 相同，多 Key 组合失效。

### 2.2 `fingerprint` 未做掩码 ⚠️ 测试失败

`KeyExtractor::fingerprint()` 原样返回 key，未脱敏。`KeyExtractorTest` 中 `test_fingerprint_masks_key` 和 `test_fingerprint_short_key` 预期失败。

### 2.3 `user_agent_patterns` Admin 表单缺失

模型 fillable 包含此字段，Seeder 设置了值，但 `ChannelAffinityRuleController` 表单中**无此配置项**。用户无法在后台配置 User-Agent 匹配。

### 2.4 `skip_retry_on_failure` 未接入重试循环

- `ChannelAffinityService::shouldSkipRetry()` 已实现
- `AffinityResult` DTO 携带 `skipRetry` 字段
- **但** `ProxyServer` / `RetryHandler` 的重试循环**从未调用**此方法

### 2.5 `param_override_template` 完全未集成

`getParamOverrideTemplate()` 方法已定义，但全代码库无任何调用点。参数覆盖功能形同虚设。

### 2.6 `include_group_in_key` 字段逻辑未实现

字段存在、Seeder 全部设为 `true`，但 `ChannelAffinityService` / `KeyExtractor` / `RuleMatcher` 中**完全未使用**。`groupName` 参数虽传入但未参与 key 生成。

### 2.7 `ChannelAffinityService` 未注册为 Singleton

`RouterServiceProvider` 注册 `ProxyServer` 为 singleton，但 `ChannelAffinityService` 未注册。`StreamHandler`/`NonStreamHandler` 通过 `app()` 解析时可能获得新实例，导致 `$lastResult` 状态丢失，`getAffinityInfo()` 可能返回 null。

## 三、设计偏差（已决策，需文档同步）

### 3.1 `model_patterns` / `path_patterns` 从 JSON 数组改为标量

| 字段 | 设计文档 | 现状 |
|------|---------|------|
| `model_patterns` | JSON 数组 `["^gpt-.*$"]` | text 标量字符串（迁移已变更） |
| `path_patterns` | JSON 数组 | varchar(255) 标量 + `PathPattern` 枚举 |

`RuleMatcher::matchModel` 用 `preg_match` 匹配单个正则；`matchPath` 用 `===` 精确匹配（非正则）。**设计文档需更新**。

### 3.2 缓存存储方式变更

设计文档描述使用 Laravel Cache（Redis），实际实现使用**数据库表** `channel_affinity_cache`。`ChannelAffinityCache` 服务类的 `buildCacheKey()` 方法成为死代码。

## 四、悬挂代码（已定义未使用）
