# 中转架构

## 整体流程

```
客户端请求 → AuthenticateApiKey → ProxyController → ProxyServer → 渠道选择 → 协议转换 → Provider调用 → 响应回传
```

## 1. 请求入口

**路由** `routes/api.php` | **控制器** `Http/Controllers/Api/ProxyController.php`

| 端点 | 协议标识 |
|------|---------|
| `POST /api/openai/v1/chat/completions` | `openai` |
| `POST /api/openai/v1/completions` | `openai` |
| `POST /api/openai/v1/embeddings` | `openai` |
| `POST /api/openai/v1/responses` | `openai_responses` |
| `POST /api/anthropic/messages` | `anthropic` |
| `GET /api/openai/v1/models` | — |
| `GET /api/anthropic/models` | — |

所有端点经 `AuthenticateApiKey` 中间件，从 `Authorization: Bearer` / `X-API-Key` / `api_key` 参数提取密钥，验证后挂载 `ApiKey` 模型到请求。

`ProxyController::handleRequest()` 将请求和协议标识传给 `ProxyServer::proxy()`，流式返回 `StreamedResponse`，非流式返回 `JsonResponse`。

## 2. ProxyServer 核心编排

**文件** `Services/Router/ProxyServer.php`

`proxy()` 方法在 `while` 循环中编排完整生命周期：

```
1. AuditLogger::createInitial()     → 创建审计日志
2. RequestLogger::create()          → 记录请求详情
3. ProtocolConverter::normalizeRequest() → 解析为协议请求对象
4. ApiKey::resolveModel()           → Key级模型映射
5. ChannelSelector::select()        → 渠道选择（亲和性优先）
6. ChannelRouterService::resolveModel() → 渠道级模型映射
7. AuditLogger::update()            → 更新渠道/协议信息
8. 协议转换（如需）                  → SharedDTO 中间格式
9. ProviderManager::getForChannel() → 获取Provider驱动
10. 创建渠道请求日志
11. 流式/非流式处理
12. 失败重试（最多3次，跨渠道故障转移）
```

### Body Passthrough

渠道配置 `body_passthrough` 时跳过协议转换，直接透传原始请求体。

### Thinking 过滤

渠道配置 `filter_request_thinking` 时，移除请求中的思维/推理块。

## 3. 渠道选择

**文件** `Services/Router/ChannelRouterService.php`

### 过滤链

```
别名扩展 → 渠道查询(status=ACTIVE, status2=NORMAL) → API Key渠道限制 → 透传协议过滤 → User-Agent过滤 → 排除已失败渠道 → 负载均衡
```

1. **别名扩展**: `ModelService::resolveModelWithAliases()` 获取模型名+所有别名的并集
2. **渠道查询**: 查 `channel_models` 表匹配模型，过滤活跃渠道，排除 CodingAccount 暂停的渠道
3. **Key渠道限制**: `allowed_channels` 白名单 + `not_allowed_channels` 黑名单
4. **透传协议过滤**: `body_passthrough` 渠道必须匹配源协议
5. **UA过滤**: `UserAgentFilterService` 匹配允许的 UA 模式

### 负载均衡策略

| 策略 | 逻辑 |
|------|------|
| `weighted_round_robin`（默认） | 按权重加权随机 |
| `least_connections` | 选 `total_requests` 最少的 |
| `response_time` | 选 `avg_latency_ms` 最低的 |

配置: `config/router.php` — `cache_ttl:60`, `max_retry:3`, `enable_failover:true`

## 4. 渠道亲和性

**文件** `Services/ChannelAffinity/`

使同一来源的请求始终路由到同一渠道（会话粘性）。

```
RuleMatcher::match() → KeyExtractor::extractKeyHash() → ChannelAffinityCache::get() → 命中则使用缓存渠道
```

- **规则匹配**: 按优先级遍历 `ChannelAffinityRule`，匹配模型正则/路径/UA
- **Key提取**: 从 header/JSON路径/查询参数/API Key ID/客户端IP/UA 提取标识，策略: `first`/`concat`/`hash`
- **缓存查找**: `channel_affinity_caches` 表查 `(rule_id, key_hash) → channel_id`
- **记录亲和性**: 请求成功后 `recordAffinity()` 写入缓存
- **安全检查**: 返回缓存渠道前验证 Key 的渠道限制，不通过则清除缓存

## 5. 协议转换

**文件** `Services/Protocol/`

### 驱动注册

| 驱动 | 协议名 | 请求DTO | 响应DTO |
|------|--------|---------|---------|
| `OpenAiChatCompletionsDriver` | `openai` | `ChatCompletionRequest` | `ChatCompletionResponse` |
| `AnthropicMessagesDriver` | `anthropic` | `MessagesRequest` | `MessagesResponse` |
| `OpenAIResponsesDriver` | `openai_responses` | `OpenAIResponsesRequest` | `OpenAIResponsesResponse` |

### 转换流程

```
源请求 → parseRequest() → 协议请求DTO → toSharedDTO() → Shared\Request → 目标DTO::fromSharedDTO() → 目标请求
```

`Shared\Request` 是协议无关的中间格式，携带 `model`/`messages`/`maxTokens`/`temperature`/`tools`/`thinking`/`stream`/`system` 等。

### 流式转换

上游 Provider 产出 `StreamChunk`，驱动通过 `buildStreamChunk()` 转为协议特定 SSE 格式：
- OpenAI: `data: {...}\n\n`
- Anthropic: `event: ...\ndata: {...}\n\n`（需跟踪 `content_block_start`/`delta`/`stop` 事件序列）

## 6. Provider 驱动

**文件** `Services/Provider/`

| Provider | 名称 | 端点 | 认证Header |
|----------|------|------|-----------|
| `OpenAIProvider` | `openai` | `/chat/completions` | `Authorization: Bearer {key}` |
| `AnthropicProvider` | `anthropic` | `/messages` | `x-api-key: {key}` + `anthropic-version` |
| `DeepSeekProvider` | `deepseek` | OpenAI兼容 | — |
| `OpenAICompatibleProvider` | 任意 | 可配置 | 可配置 |

`ProviderManager::getForChannel()` 根据渠道配置运行时实例化 Provider。

### 核心能力

- **send()**: 同步请求，内部指数退避重试
- **sendStream()**: 流式请求，PSR-7 响应体按 `\n\n` 解析 SSE
- **熔断器**: `closed → open → half-open`，阈值5次失败，防止向故障Provider发请求
- **Header转发**: 通配符匹配客户端Header转发到上游（排除黑名单如 `x-api-key`）
- **Body Passthrough**: DTO 含 `rawBodyString` 时直接发送原始JSON

### 错误分类

| 类型 | 可重试 | 说明 |
|------|--------|------|
| `network_error` | ✅ | 网络错误 |
| `rate_limit_exceeded` | ✅ | 429限流 |
| `server_error` | ✅ | 5xx |
| `timeout` | ✅ | 超时 |
| `authentication_error` | ❌ | 401认证失败 |
| `invalid_request` | ❌ | 400请求无效 |
| `model_not_found` | ❌ | 模型不存在 |
| `context_length_exceeded` | ❌ | 上下文超长 |
| `content_filter` | ❌ | 内容过滤 |

## 7. 模型映射（三层）

```
客户端请求模型 → Key级映射(ApiKey.model_mappings) → 别名扩展(ModelList.aliases) → 渠道级映射(channel_models.mapped_model)
```

1. **Key级**: `ApiKey.model_mappings` JSON映射，如 `{"gpt-4": "gpt-4-turbo"}`
2. **别名扩展**: `ModelList.aliases` 扩展模型名用于渠道查找
3. **渠道级**: `channel_models.mapped_model` 渠道内部重写模型名

Key级限制: `allowed_models` 限制可用模型，`allowed_channels`/`not_allowed_channels` 限制渠道

## 8. 重试与故障转移

### 两层重试

**A. ProxyServer层（跨渠道）**

`while ($attempt <= $maxRetries)` 循环：
- `RetryHandler::shouldRetry()`: 故障转移启用 + 尝试次数 < 3 + 状态码可重试(429/5xx)
- `ChannelSelector::markFailed()`: 标记失败渠道，排除后续选择
- `RetryHandler::wait()`: 指数退避 `100ms * 2^(attempt-1)`，上限1秒
- 重新选择不同渠道

**B. Provider层（单渠道）**

`AbstractProvider` 内部重试循环，仅重试瞬态错误（网络/限流/5xx/超时）。

### 熔断器

Provider 跟踪连续失败次数，达阈值(5)后熔断器打开，直接抛 `circuitOpen` 异常，超时后进入半开状态。

## 9. 日志系统

| 表 | 记录器 | 内容 |
|----|--------|------|
| `audit_logs` | `AuditLogger` | 请求ID、Key、模型、协议、渠道、状态码、延迟、Token、错误 |
| `request_logs` | `RequestLogger` | 请求体、Header、模型参数、提示内容 |
| `channel_request_logs` | — | 完整的上下游请求/响应URL、Header、Body、大小、延迟 |
| `response_logs` | `ResponseLogger` | 响应体、状态、Token用量、完成原因、流式块 |

### 审计日志流程

```
createInitial() → [渠道选择后] update() → [响应完成] update(状态码/延迟/Token) → [错误] handleError()
```

## 10. 完整请求流程图

```
Client POST /api/openai/v1/chat/completions
  │
  ▼
AuthenticateApiKey: 提取Key → 查找ApiKey模型 → 挂载到请求
  │
  ▼
ProxyController::handleRequest($request, 'openai')
  │
  ▼
ProxyServer::proxy($request, 'openai')
  ├─ AuditLogger::createInitial()
  ├─ RequestLogger::create()
  ├─ normalizeRequest() → ChatCompletionRequest
  ├─ ApiKey::resolveModel() [Key级映射]
  │
  ├─ ChannelSelector::select()
  │   ├─ ChannelAffinityService::getPreferredChannel()
  │   │   ├─ RuleMatcher::match() [规则匹配]
  │   │   ├─ KeyExtractor::extractKeyHash() [提取标识]
  │   │   └─ ChannelAffinityCache::get() [查缓存]
  │   └─ (未命中) ChannelRouterService::selectChannel()
  │       ├─ 别名扩展 → 渠道查询 → Key限制 → 协议过滤 → UA过滤
  │       └─ 负载均衡选择
  │
  ├─ resolveModel() [渠道级映射]
  ├─ AuditLogger::update() [渠道信息]
  │
  ├─ [协议不同] convertRequest(): ChatCompletionRequest → SharedDTO → MessagesRequest
  ├─ [body_passthrough] 跳过转换，透传原始体
  │
  ├─ ProviderManager::getForChannel() → AnthropicProvider
  ├─ createChannelRequestLog()
  │
  ├─ [流式] StreamHandler::handle()
  │   ├─ provider->sendStream() → SSE流
  │   ├─ 逐块 convertStreamChunk() + yield
  │   ├─ AuditLogger更新 / recordAffinity() / ResponseLogger
  │   └─ updateChannelRequestLog()
  │
  ├─ [非流式] NonStreamHandler::handle()
  │   ├─ provider->send() → JSON响应
  │   ├─ convertResponse() → 协议格式
  │   └─ AuditLogger更新 / recordAffinity() / ResponseLogger
  │
  └─ [异常] 重试循环(最多3次)
      ├─ markFailed() → 排除渠道
      ├─ wait() → 指数退避
      └─ 重新选择渠道
```
