# 数据库安全配置指南

## 问题：如何彻底杜绝数据丢失？

**答案：从数据库权限层面限制，应用账号不应有 TRUNCATE/DROP 权限。**

## 立即实施方案

### 1. 创建受限的应用账号

```sql
-- 1. 创建新的应用用户（替换现有 cdapi 用户）
CREATE USER 'cdapi_app'@'%' IDENTIFIED BY '新的强密码';

-- 2. 只授予必要的 DML 权限（SELECT/INSERT/UPDATE/DELETE）
GRANT SELECT, INSERT, UPDATE, DELETE ON cdapi.* TO 'cdapi_app'@'%';

-- 3. 不授予 DDL 权限（DROP/TRUNCATE/ALTER/CREATE）
-- 这样即使代码中有 truncate，也会因权限不足而失败

-- 4. 刷新权限
FLUSH PRIVILEGES;
```

### 2. 创建管理账号（仅用于迁移）

```sql
-- 1. 创建管理用户（仅 DBA 使用）
CREATE USER 'cdapi_admin'@'%' IDENTIFIED BY '另一个强密码';

-- 2. 授予完整权限（包括 DDL）
GRANT ALL PRIVILEGES ON cdapi.* TO 'cdapi_admin'@'%';

-- 3. 刷新权限
FLUSH PRIVILEGES;
```

### 3. 修改应用配置

```bash
# .env - 应用使用受限账号
DB_USERNAME=cdapi_app
DB_PASSWORD=新的强密码
```

### 4. 创建迁移专用配置

```php
// config/database.php
'connections' => [
    'mysql' => [
        // 应用连接 - 使用受限账号
        'username' => env('DB_USERNAME', 'cdapi_app'),
        'password' => env('DB_PASSWORD', ''),
    ],

    'mysql_admin' => [
        // 管理连接 - 用于迁移等操作
        'driver' => 'mysql',
        'host' => env('DB_HOST', '127.0.0.1'),
        'port' => env('DB_PORT', '3306'),
        'database' => env('DB_DATABASE', 'cdapi'),
        'username' => env('DB_ADMIN_USERNAME', 'cdapi_admin'),
        'password' => env('DB_ADMIN_PASSWORD', ''),
        // ... 其他配置
    ],
],
```

```bash
# .env - 管理账号（仅在需要时配置）
DB_ADMIN_USERNAME=cdapi_admin
DB_ADMIN_PASSWORD=另一个强密码
```

### 5. 修改迁移命令

```php
// app/Console/Commands/SafeDatabaseReset.php

public function handle(): int
{
    // 切换到管理连接
    $defaultConnection = config('database.default');
    config(['database.default' => 'mysql_admin']);

    DB::purge('mysql_admin');
    DB::reconnect('mysql_admin');

    // 执行迁移
    $this->call('migrate:fresh', ['--seed' => true]);

    // 切回应用连接
    config(['database.default' => $defaultConnection]);
    DB::purge('mysql');
    DB::reconnect('mysql');

    return self::SUCCESS;
}
```

## 效果

### 代码层面
- ❌ `DB::table('users')->truncate()` → **权限错误**
- ❌ `DB::statement('DROP TABLE users')` → **权限错误**
- ✅ `DB::table('users')->delete()` → 正常执行

### 命令层面
- ❌ `php artisan migrate:fresh` → **权限错误**
- ✅ `php artisan cdapi:safe-reset` → 需要确认，自动备份

### 迁移层面
- ✅ 迁移文件中的 `Schema::create()` → 需要管理账号
- ❌ 迁移文件中的 `Schema::dropIfExists()` → 需要管理账号
- ✅ 使用 `SafeDatabaseReset` 命令执行

## 备份策略

### 自动备份
```bash

0 2 * * * cd /path/to/laravel && php artisan cdapi:backup:table --group=all
```

### 操作前备份
```bash
# 执行危险操作前手动备份
php artisan cdapi:backup:table --group=core
```

## 权限分离总结

| 用户 | 权限 | 用途 |
|------|------|------|
| `cdapi_app` | SELECT, INSERT, UPDATE, DELETE | 应用日常使用 |
| `cdapi_admin` | ALL PRIVILEGES | 迁移、备份等管理操作 |

**关键点**：
- 应用运行时使用 `cdapi_app`，无法执行 truncate/drop
- 迁移操作需要手动切换到 `cdapi_admin` 或使用 `SafeDatabaseReset`
- 即使代码中有 truncate，也会因权限不足而安全失败
